# راهنمای راه‌اندازی AZ COFFEE

سایت استاتیک است (HTML + CSS + JS) و محصولات و اطلاعات تماسش را از فایل‌های `products.json` و `settings.json` می‌خواند. این دو فایل را می‌توانید از پنل مدیریت (Decap CMS) ویرایش کنید.

## ساختار پروژه

```
├── index.html          صفحه‌ی اصلی
├── style.css           استایل‌ها
├── script.js           منطق سایت (محصولات، سبد، فرم پرداخت)
├── products.json       محصولات
├── settings.json       متن صفحه‌ی اصلی + اطلاعات تماس + شماره‌ی دریافت سفارش
├── favicon.svg · 404.html · robots.txt
├── images/
│   ├── placeholder.svg  تصویر جایگزین (اگر عکس محصول باز نشد)
│   └── uploads/         عکس‌هایی که از پنل آپلود می‌کنید
└── admin/
    ├── index.html      صفحه‌ی پنل مدیریت
    └── config.yml      تنظیمات پنل
```

پوشه‌ی جداگانه‌ی `azcoffee-oauth-worker/` فقط برای ورود به پنل مدیریت است و **داخل سایت آپلود نمی‌شود** (بخش ۵).

---

## ۱) قبل از انتشار: تنظیم `settings.json`

فایل `settings.json` را باز کنید و اطلاعات فروشگاه را پر کنید:

| کلید | توضیح |
|---|---|
| `phone` | تلفن تماس |
| `whatsapp` | شماره‌ی واتس‌اپ (فقط برای نمایش در بخش تماس) |
| `telegram` · `instagram` | آیدی بدون @ |
| `email` · `address` · `working_hours` | اختیاری |
| `shipping_note` | متنی که زیر فرم پرداخت نمایش داده می‌شود (مثلاً هزینه‌ی ارسال) |

هر کلیدی که خالی بماند، در سایت نمایش داده نمی‌شود. بعداً همین موارد را از پنل مدیریت («تنظیمات سایت و تماس») هم می‌توانید عوض کنید.

## ۲) آپلود روی GitHub

1. در github.com روی **New repository** بزنید، نام مخزن را (مثلاً `az-coffee`) بنویسید و **Public** را انتخاب کنید.
2. **uploading an existing file** را بزنید و همه‌ی فایل‌ها و پوشه‌های داخل `azcoffee` را آپلود کنید (محتوای پوشه، نه خود پوشه؛ یعنی `index.html` باید در ریشه‌ی مخزن باشد).
   اگر پوشه‌ها آپلود نشد (مثلاً در موبایل): **Add file ← Create new file** و در کادر نام، مسیر را با `/` تایپ کنید، مثل `admin/index.html`.
3. **Commit changes** را بزنید.

## ۳) فعال‌سازی GitHub Pages و دامنه

1. **Settings ← Pages ← Source: Deploy from a branch ← Branch: `main` و پوشه‌ی `/ (root)` ← Save**
2. بعد از یکی دو دقیقه آدرس سایت بالای همان صفحه نمایش داده می‌شود.
3. برای دامنه‌ی اختصاصی، در همان صفحه در بخش **Custom domain** دامنه را بنویسید و Save کنید. سپس در DNS دامنه:
   - چهار رکورد **A** برای دامنه‌ی اصلی: `185.199.108.153` و `185.199.109.153` و `185.199.110.153` و `185.199.111.153`
   - یک رکورد **CNAME** برای `www` به `YOUR-USERNAME.github.io`
4. چند دقیقه تا چند ساعت بعد، **Enforce HTTPS** را فعال کنید.

> آدرس‌های IP را با مستندات رسمی GitHub Pages تطبیق دهید؛ ممکن است تغییر کرده باشند.

## ۴) فعال‌سازی پنل مدیریت (`/admin`)

آدرس پنل: `https://دامنه-شما/admin/`

فایل `admin/config.yml` را باز کنید و دو مقدار را عوض کنید:
- `repo:` ← `نام-کاربری-گیت‌هاب/نام-مخزن`
- `base_url:` ← آدرس Worker ورود (بخش ۵)

> **بدون بخش ۵ ورود به پنل ممکن نیست.** تا آن موقع، `products.json` و `settings.json` را می‌توانید مستقیم در GitHub ویرایش کنید (آیکون مداد). مراقب کاما و گیومه‌ها باشید.

### کار با پنل
- **لیست محصولات:** افزودن، حذف، تغییر قیمت، عکس، توضیح و موجودی.
- **تنظیمات سایت و تماس:** متن صفحه‌ی اصلی، شماره‌ها و آدرس.
- در پایان **Publish** را بزنید. بعد از ۱ تا ۲ دقیقه روی سایت دیده می‌شود.
- `id` هر محصول باید یکتا باشد (مثلاً `az-007`).
- عکس‌ها را افقی (۴:۳) و سبک (زیر ۳۰۰ کیلوبایت) آپلود کنید تا سایت سریع بماند.

## ۵) ساخت Worker ورود برای پنل (یک‌بار، حدود ۱۰ دقیقه)

Decap CMS برای ورود با GitHub به یک واسطه نیاز دارد. این کار رایگان است.

1. **GitHub OAuth App:** GitHub ← **Settings ← Developer settings ← OAuth Apps ← New OAuth App**
   - Homepage URL: آدرس سایت شما
   - Authorization callback URL: فعلاً یک مقدار موقت (بعد از مرحله‌ی ۳ اصلاح می‌شود)
2. در **cloudflare.com** حساب رایگان بسازید و از **Workers & Pages ← Create ← Worker** یک Worker بسازید. محتوای فایل `azcoffee-oauth-worker/worker.js` را در آن جایگزین و Deploy کنید.
3. آدرس Worker (مثلاً `https://az-auth.xxx.workers.dev`) را کپی کنید و در OAuth App، **Authorization callback URL** را بگذارید: `آدرس-Worker/callback`
4. در Worker ← **Settings ← Variables and Secrets** این سه مقدار را اضافه کنید:
   - `GITHUB_CLIENT_ID` (از OAuth App)
   - `GITHUB_CLIENT_SECRET` (از OAuth App، نوع Secret)
   - `ALLOWED_ORIGIN` ← آدرس سایت شما، مثلاً `https://azcoffee.ir` (بدون `/` آخر؛ حتماً با همان آدرسی که پنل را از آن باز می‌کنید یکی باشد)
5. آدرس Worker را در `base_url` فایل `admin/config.yml` بگذارید.
6. به `/admin/` بروید و **Login with GitHub** را بزنید. فقط حساب‌هایی که به مخزن دسترسی نوشتن دارند می‌توانند ذخیره کنند.

> اگر مخزن شما Private است، در `worker.js` مقدار `SCOPE` را به `'repo'` تغییر دهید.

## ۶) اتصال درگاه پرداخت (بعداً)

در سایت هیچ کد درگاهی نیست. سبد خرید و فرم (نام، تلفن، آدرس) و دکمه‌ی «پرداخت» کار می‌کنند، ولی تا وقتی درگاه وصل نشود، زدن «پرداخت» فقط پیام «پرداخت آنلاین هنوز فعال نشده» را نشان می‌دهد و سبد حفظ می‌شود.

محل اتصال درگاه فقط یک تابع است: `window.AZ_ORDER_HANDLER`. مراحل:

1. یک سرور کوچک یا تابع Serverless (Cloudflare Workers، Vercel، Netlify Functions یا سرور ایرانی) بسازید که از API زرین‌پال/آیدی‌پی لینک پرداخت بسازد و بعد از بازگشت کاربر، تراکنش را **Verify** کند. مرچنت‌کد را فقط همان‌جا نگه دارید، نه در فایل‌های سایت.
2. فایلی به نام `payment.js` کنار `index.html` بسازید:

```js
// payment.js
window.AZ_ORDER_HANDLER = async function (order, api) {
  // order: { code, customer:{name,phone,address}, items:[{id,name,qty,price}], total, createdAt }
  const res = await fetch('https://آدرس-سرور-شما/create-payment', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(order)
  });
  if (!res.ok) throw new Error('payment error');   // پیام خطا خودکار به مشتری نشان داده می‌شود
  const data = await res.json();                   // انتظار: { paymentUrl: 'https://...' }
  window.location.href = data.paymentUrl;          // رفتن به درگاه بانک
};
```
3. در انتهای `index.html` کامنت خط `<script src="payment.js"></script>` را بردارید.
4. سبد را بعد از **تأیید موفق پرداخت** خالی کنید (مثلاً در صفحه‌ی بازگشت از درگاه با پاک کردن `localStorage` کلید `azcoffee_cart_v1`)، نه قبل از آن.
5. مبلغ را سرور باید از روی `items` و **قیمت‌های خودش** دوباره حساب کند، نه از `order.total` ارسالی مرورگر. واحد مبلغ را هم بررسی کنید (زرین‌پال تومان را می‌پذیرد؛ آیدی‌پی ریال می‌خواهد).

درگاه‌های ایرانی معمولاً قبل از فعال‌سازی سایت را بررسی می‌کنند و ممکن است اینماد بخواهند.

## ۷) چک‌لیست قبل از معرفی سایت

- [ ] `settings.json` پر شده است
- [ ] قیمت‌ها و توضیحات محصولات واقعی است (نمونه‌ها را عوض کنید)
- [ ] عکس‌های محصول را خودتان آپلود کرده‌اید (عکس‌های نمونه از Unsplash هستند)
- [ ] HTTPS فعال است
- [ ] روی موبایل واقعی سایت را باز و تست کرده‌اید

## نکات

- **تست روی کامپیوتر:** فایل را با دوبار کلیک باز نکنید (بارگذاری JSON کار نمی‌کند). در پوشه‌ی پروژه `python3 -m http.server 8000` را اجرا و `http://localhost:8000` را باز کنید.
- **فونت:** وزیرمتن از Google Fonts لود می‌شود. اگر برای بعضی کاربران باز نشد، فونت Tahoma جایگزین می‌شود و سایت سالم می‌ماند. برای قطعیت بیشتر می‌توانید فایل فونت را دانلود و خودتان میزبانی کنید.
- **سبد خرید** در مرورگر مشتری ذخیره می‌شود و با رفرش از بین نمی‌رود.
- بعد از هر تغییر در GitHub Pages، تا ۱۰ دقیقه ممکن است نسخه‌ی قبلی از کش نمایش داده شود.
